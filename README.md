# iNode for Mac

西南财经大学宿舍有线网络认证客户端，使用 SwiftUI 编写。提供普通 iNode 认证和 macOS 有线 PEAP 认证，支持 Apple Silicon 与 Intel Mac，最低系统版本为 macOS 13。

普通认证调用 H3C Mac PC 7.3 (E0585) 引擎，已由使用者在毅园移动宿舍网口确认连接成功。其他宿舍网口及 Intel Mac 尚未经过现场验证。PEAP 是备选方式，目前也没有成功连接的现场验证。

应用默认只在菜单栏显示图标，不占用 Dock。手动打开应用会显示主窗口；登录时自动启动则只显示菜单栏图标。点击窗口左上角红色关闭按钮会隐藏主窗口，应用和认证服务继续在菜单栏运行；黄色最小化按钮才会把窗口留在 Dock。点击菜单栏图标可重新打开主界面，也可选择“重启 iNode for Mac”或“退出 iNode for Mac”。主界面操作区也有“重启软件”按钮，并可选择在窗口打开期间显示 Dock 图标。重启时会接管仍在运行的授权组件和认证会话，不主动断开网络；授权组件存活时无需重新输入管理员密码。完全退出则结束认证会话。若正在等待管理员授权，需先完成或取消弹窗再重启。

认证中、等待自动重试和认证通过后，窗口都会自动收紧，把连接信息和操作按钮放在紧凑视图内；连接结束后恢复较高的账号编辑界面。左侧设置区域可独立滚动。主界面只显示易读的认证阶段，E0585 控制参数等技术详情保留在连接日志中。

启动时，如果选中的有线网卡已接入并取得 IPv4 地址，应用先通过该网卡测试 Google 和百度；任一可访问便直接显示“已连接”，不重复提交校园网账号。此时“认证状态”会注明是有线网卡联网检测，而非原厂引擎的新认证结果。若网卡刚接入但尚无地址，自动连接前最多等待约 4 秒，让已联网的网卡有机会取得地址并完成检测；检测未通过后再按“启动后自动连接”设置尝试认证。认证通过后，应用约每 2 秒检查一次所选有线网卡的 IPv4 地址，并约每 30 秒通过该网卡复查 Google 和百度。等待地址期间主界面显示“正在等待学校服务器分配 IP 地址…”。两项网站检测每项最长 7 秒，也可以点“刷新状态”立即复查。没有取得有线 IP 时，“刷新状态”只重新检查地址，不会提前测试网站。

## 下载与安装

从 [Releases](https://github.com/silenzio111/inode-for-mac/releases) 下载对应芯片的 ZIP：`arm64` 用于 M 系列芯片，`x86_64` 用于 Intel。解压后先将 `iNode for Mac.app` 移至“应用程序”，再打开。两个包分别包含对应架构的应用和辅助程序，并附带普通认证所需的 H3C Mac PC 7.3 (E0585) 原厂引擎及配套库；该引擎本身是 x86_64，因此 M 系列芯片使用普通认证还需要 [Rosetta 2](https://support.apple.com/102527)。

H3C 组件来自 [`helson-lin/iNode_Client_Sequoia`](https://github.com/helson-lin/iNode_Client_Sequoia) 的固定提交 `dd9ac3f26815c262a67a3e434bfaa2e6f178d510`。本项目的 GPL 许可仅覆盖自编源码，**不将 H3C 原厂组件声明为开源**；上游封装项目的 MIT 声明也不能替代原厂组件的权利归属。详情见 [THIRD_PARTY.md](THIRD_PARTY.md)。从完全退出状态启动后，首次普通认证会请求管理员授权；保持应用运行或使用应用内“重启软件”时，可复用仍在运行的已授权后台组件。完全退出应用后再启动，需要重新授权。公开包未经 Apple Developer ID 公证，首次打开可能需到“系统设置 → 隐私与安全性”允许。

已经使用旧版连接时，无须为更新图标断开网络；方便重新连接时再退出旧版并打开新版。

主界面的“启动与显示”中可开启开机自启，并选择启动后使用上次配置自动连接。先勾选“本机加密保存账号与密码”并连接一次，才有可用于下次自动连接的账号、密码和网卡配置。0.7.0 不再读取旧版钥匙串密码；升级后需重新输入密码一次。旧钥匙串条目不会被自动删除。若启动时网线尚未接入，应用会在菜单栏等待网卡接入。建议先将应用移至“应用程序”，再开启开机自启；移动应用后请关闭并重新开启该选项，以更新启动路径。
认证会话意外结束、认证组件启动超时或认证所用网卡断开后，应用默认自动重试 3 次，每次间隔约 3 秒；网线未接入时会等待重新接入。可在左侧设为 0–10 次，0 表示关闭。主动断开或取消管理员授权不会触发重试。认证成功之前，网络地址步骤不会显示为已获取。

## 使用

选择已接入的有线网卡，输入学号与校园网密码。建议在认证完成后再启用代理软件。移动账号选择“移动（@cm）”，应用会在没有后缀时补全 `@cm`；若账号已有后缀，按原样提交。普通认证是本项目已经现场连通的方式。只有系统或原厂引擎报告校园网认证通过时，界面才标为“已通过”。

联网测试只访问 Google 和百度：普通 HTTPS 请求禁用代理配置并绑定所选有线网卡，另用直接 TLS 连接复核。若代理软件把域名解析成 `198.18/15` 虚拟地址，应用还会通过 Google 的加密 DNS 获取百度真实地址，并用该地址从所选有线网卡直接访问百度；DNS 查询本身不会被算作联网成功。任一最终 HTTPS 测试通过时，界面显示“网络连接正常”。这些方法能减少 HTTP 代理和虚拟 DNS 的干扰，但无法绕过接管底层网络流量的透明 VPN。测试成功说明该网卡可访问网站，但不等于读取到了校园网服务器的认证结果。账号和密码可选用应用内 AES-GCM 加密保存，密文与随机密钥保存在当前用户的私有应用支持目录，启动时不调用 macOS 钥匙串。这能避免明文存盘，但同一用户权限下的其他进程仍可同时读取密文与密钥，保护强度低于系统钥匙串。应用日志不记录明文账号、密码或原始认证报文。

## 从源码构建

在 macOS 与 Xcode Command Line Tools 环境中：

```sh
./scripts/create_icon.sh
INODE_ENGINE_DESTINATION="$PWD/.build/vendor-mac" ./scripts/install_engine.sh
./scripts/package_release.sh
```

`install_engine.sh` 从固定提交取得组件并在本地准备，不执行上游安装脚本。`package_release.sh` 将组件分别打入 ARM 与 Intel 应用包。如只需自行编译本项目源码、不打入第三方二进制，可使用 `INODE_INCLUDE_VENDOR=0 INODE_ARCH=arm64 ./scripts/build.sh`（Intel 改为 `x86_64`）；此时普通认证需要另行在本机安装组件。

```sh
./scripts/test.sh
./scripts/test_native.sh
INODE_APP_OUTPUT='dist/release/iNode for Mac-arm64.app' python3 scripts/test_peap.py
```

`test_native.sh` 默认只运行独立源码测试。若本机已有 `research/inode-modern` 和 `.build/vendor-mac`，且当前没有运行中的 iNode 认证会话，可设置 `INODE_TEST_VENDOR=1` 额外进行协议基线与离线管道检查。测试使用虚构凭据和不存在的网卡，不会对真实网口发起认证。
